## SSRF and outbound-fetch rules (apply to audit and screenshots)
- The endpoints take a **lead id**, never a URL. The server looks up that lead's own `Website URL` and only ever fetches that. No arbitrary-URL parameter anywhere.
- Before fetching: scheme must be http/https; resolve the hostname and refuse loopback, private (10/8, 172.16/12, 192.168/16), link-local (169.254/16 incl. metadata), CGNAT/Tailscale (100.64/10), IPv6 equivalents and `.local/.internal`. Re-check on every redirect hop (or refuse redirects to non-public targets), cap redirects, response size (e.g. 2 MB for audit) and time (10 s audit / 20 s screenshot). For the headless browser, verify the final URL/IP after load and discard the shot if it landed somewhere non-public; state the residual risk plainly in plan.md.
- Tests must prove the guards refuse: `http://127.0.0.1:3041/`, `http://100.78.149.77:8768/`, `http://169.254.169.254/`, `http://localhost/`, a hostname that resolves to a private IP, a public URL that redirects to `http://127.0.0.1/`. A guard test whose "refused" branch was never shown reachable does not count: break the guard on purpose and show the test go red.
- Screenshot cache: disk cache under a CRM-owned dir, keyed by lead id + URL hash, TTL like the old one, size-bounded.
